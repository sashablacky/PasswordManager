This is a local only password manager with breach detection and password generator

Runs on Windows and macOS (Python 3.12, PyQt5 + PyQt-Fluent-Widgets). Changes by version: `CHANGES.md`.

## Running from the sources

```
python -m venv .venv
.venv\Scripts\activate            # macOS: source .venv/bin/activate
pip install -r requirements.txt
python src/main.py
```

Tests: `python -m pytest` (on Windows without a screen set `QT_QPA_PLATFORM=offscreen`).

## Where the data is

| | Folder |
|---|---|
| Windows | `%APPDATA%\SecureVault` |
| macOS | `~/Library/Application Support/SecureVault` |
| Linux | `$XDG_DATA_HOME/SecureVault` or `~/.local/share/SecureVault` |

It holds the encrypted vault `password_vault.db`, `settings.json` (theme) and `error.log`.
On macOS and Linux the folder is owner-only (0700) and the vault, backups and CSV
exports are created owner-only (0600).

## Windows

Installing on Windows (in Russian): [`docs/windows-install.md`](docs/windows-install.md).

Download from the Releases page (no GitHub account needed):
https://github.com/sashablacky/PasswordManager/releases/latest —
`...-Windows-Setup.exe` (installer) or `...-Windows-Portable.zip` (no installation).

- The installer (Inno Setup, `packaging/windows/installer.iss`) installs for the
  current user only, without administrator rights, into
  `%LOCALAPPDATA%\Programs\Password Manager`, with a Start menu shortcut and an
  optional desktop shortcut. Uninstalling removes the program but keeps the vault,
  settings and log in `%APPDATA%\SecureVault`.
- The program is not code-signed, so SmartScreen may show "Windows protected your
  PC": **More info** → **Run anyway**.
- Built by the GitHub Actions workflow **Build Windows app**
  (`.github/workflows/build-windows.yml`, on every push to `main`; a `v<version>`
  tag publishes the release):
  tests, PyInstaller (`packaging/windows/PasswordManager.spec`, version details in
  the .exe properties, icon `packaging/windows/SecureVault.ico` from
  `make_ico.py`), a 20-second start on the runner's desktop with an empty
  `error.log`, the portable .zip, the installer, and a silent install → start →
  uninstall check that the vault is kept.
- Build by hand: `pip install -r requirements.txt -r packaging/windows/requirements-build.txt`,
  then `pyinstaller --noconfirm --clean packaging/windows/PasswordManager.spec`.

## macOS

Installing on a Mac without a terminal (in Russian): [`docs/macos-install.md`](docs/macos-install.md).

### Getting the app

The Mac version is frozen at v1.5.5 on the `macos-stable` branch until it works
on Intel Macs; `main` is developed for Windows only and builds no `.dmg`.
Download: https://github.com/sashablacky/PasswordManager/releases/tag/v1.5.5 —
`...-macOS-AppleSilicon.dmg` for M1 and later, `...-macOS-Intel.dmg` for Intel Macs.

The workflow **Build macOS app** (`.github/workflows/build-macos.yml` on
`macos-stable`) runs on every push to that branch: tests on macOS, then
`Password Manager.app` for Apple Silicon (`macos-14`) and Intel (`macos-15-intel`)
in a `.dmg`, kept under **Artifacts** of the run for 30 days. A Mac fix is
committed to `macos-stable` with a new version in `src/version.py`, then
`git tag mac-v<version> && git push origin mac-v<version>` publishes a release
with both `.dmg` files that is not marked "latest" (that is the Windows one);
update the link in `docs/macos-install.md` to the new release.

To build on a Mac by hand: `./packaging/macos/build_macos.sh`
(needs Python 3.12; result in `dist/`). The recipe is
`packaging/macos/PasswordManager.spec`; the icon `packaging/macos/SecureVault.icns`
is generated by `packaging/macos/make_icns.py` from the window icon.

### What differs from Windows

- Shortcuts use ⌘ instead of Ctrl (⌘N, ⌘F, ⌘G, ⌘L, ⌘Q); in addition ⌘R refreshes
  and ⌘⌫ deletes the selected entry (F5 and Delete need the Fn key on a Mac).
- Native traffic-light window buttons; no Mica (Windows 11 only), the theme's own
  backdrop is drawn instead. Fonts: SF Pro if installed, otherwise Helvetica Neue;
  Menlo for passwords.
- A copied password is marked as concealed/transient on the macOS pasteboard
  (nspasteboard.org convention), so clipboard managers do not keep it, and is
  cleared after 30 s as on Windows. Universal Clipboard (Handoff) may still show it
  on the user's other Apple devices for that time.
- Export/backup dialogs suggest the Documents folder (an app started from Finder
  has `/` as its working folder).

### Signing and notarization

The builds are signed **ad hoc** (`codesign -s -`): enough for Apple Silicon to run
them, but Gatekeeper treats them as coming from an unidentified developer. The
first start needs right click (Control-click) → **Open**; on macOS 15 and later
the right-click route is gone and the user has to press **Open Anyway** in
System Settings → Privacy & Security (see `docs/macos-install.md`).

To get rid of that, sign with a Developer ID and notarize (Apple Developer
Program, 99 USD/year):

```
export MACOS_CODESIGN_IDENTITY="Developer ID Application: Name (TEAMID)"
./packaging/macos/build_macos.sh          # signs with the hardened runtime
codesign --sign "$MACOS_CODESIGN_IDENTITY" --timestamp dist/PasswordManager-*.dmg
xcrun notarytool submit dist/PasswordManager-*.dmg \
    --apple-id you@example.com --team-id TEAMID --password <app-specific password> --wait
xcrun stapler staple dist/PasswordManager-*.dmg
```

Not tried yet: the hardened runtime may need an entitlements file for the
bundled Python (`com.apple.security.cs.disable-library-validation`,
`com.apple.security.cs.allow-unsigned-executable-memory`), passed as
`entitlements_file` in the spec. In CI this needs the certificate and the
Apple ID password as repository secrets; not set up yet.
