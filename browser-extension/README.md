# SecureVault в браузере (Firefox и Safari)

Расширение заполняет логины и пароли из программы SecureVault, предлагает сохранить новый пароль после входа на сайт и придумывает надёжные пароли при регистрации. Пароли остаются в программе: расширение получает только записи для открытого сайта и только пока программа запущена и разблокирована.

```
расширение ──native messaging──► посредник ──локальный сокет──► программа SecureVault
              (Firefox: native-host/securevault_host.py, Safari: SafariWebExtensionHandler.swift)
```

## Что где лежит

| Папка | Что это |
|---|---|
| `extension/` | Само расширение (одно для Firefox и Safari) |
| `native-host/` | Посредник для Firefox (Python, только стандартная библиотека) |
| `install_firefox.py` | Регистрирует посредника в Firefox (Windows, macOS, Linux) |
| `safari/` | Обработчик на Swift и скрипт сборки Xcode-проекта для Safari |
| `../src/integration/` | Сторона программы: сервер, сопряжение, ответы на запросы |

## Firefox (Windows и macOS)

1. Запустите программу SecureVault и разблокируйте её.
2. Зарегистрируйте посредника:
   * **Windows, программа из установщика** `Setup.exe`: ничего делать не нужно. Установщик кладёт рядом с программой `securevault_host.exe` и регистрирует его в Firefox, а при удалении программы убирает регистрацию.
   * **Portable-версия, запуск из исходников и macOS:** один раз запустите скрипт той же Python, на которой работает программа:
     ```
     .venv\Scripts\python browser-extension\install_firefox.py        (Windows)
     .venv/bin/python browser-extension/install_firefox.py            (macOS)
     ```
     Удалить: тот же скрипт с `--remove`. На Windows запускайте его из обычного PowerShell, а не из приложения, установленного из Microsoft Store или как MSIX-пакет: такому приложению Windows подсовывает собственную копию реестра, и Firefox регистрацию не увидит.
3. Установите расширение:
   * для проверки: `about:debugging` → «Этот Firefox» → «Загрузить временное дополнение» → `extension/manifest.json`. Работает до перезапуска Firefox;
   * насовсем: обычный Firefox ставит только подписанные расширения. Подписать бесплатно можно на addons.mozilla.org как «unlisted» (без публикации в каталоге): `npx web-ext sign --channel=unlisted --source-dir extension --api-key … --api-secret …`. Получится `.xpi`, который ставится в любой Firefox.
4. Нажмите на значок SecureVault на панели → «Подключить». Откроется вкладка с кодом, а программа спросит, разрешить ли Firefox доступ. Если коды совпадают, нажмите **Allow**.

Пока расширение установлено и включено, встроенный менеджер паролей Firefox выключен (разрешение `privacy`, настройка «Запрашивать сохранение логинов и паролей»), чтобы он не предлагал сохранять и не заполнял те же логины поверх SecureVault. Сохранённые в Firefox пароли остаются на месте. При отключении или удалении расширения Firefox сам возвращает прежнее значение настройки.

На Mac посреднику для Firefox нужен Python 3 (готовое приложение `.app` его не содержит). Для Safari Python не нужен.

## Safari (нужен Mac с Xcode)

Пошаговая инструкция для того, кто настраивает Mac: [docs/safari-install.md](../docs/safari-install.md).

1. На Mac: `sh browser-extension/safari/build_safari.sh`. Скрипт создаст Xcode-проект в `safari/build/`, подставит наш обработчик и настроит App Group `$(TeamIdentifierPrefix)securevault.bridge`.
2. Откройте проект в Xcode, в Signing & Capabilities у обеих целей выберите свой Apple ID (подойдёт бесплатный), нажмите Run.
3. Safari → Настройки → Расширения → включите SecureVault и разрешите его на всех сайтах. Для сборки без подписи в меню «Разработка» есть «Разрешить неподписанные расширения», но этот флажок сбрасывается после перезапуска Safari.
4. Запустите программу SecureVault (она сама находит папку App Group и начинает слушать в ней) и подключите браузер так же, как Firefox.

На macOS 15 при первом подключении система может спросить, разрешить ли программе доступ к данным других приложений: это и есть папка App Group, нужно разрешить.

## Как это защищено

* **Сопряжение.** Браузер и программа обмениваются ключами (ECDH P-256) и показывают одинаковый шестизначный код. Пока пользователь не нажал Allow в программе, браузер ничего не получает. После этого у каждого браузера свой 32-байтовый ключ; в программе он хранится зашифрованным ключом хранилища, поэтому копия базы бесполезна, а при заблокированной программе ни один браузер не пройдёт проверку.
* **Шифрование.** Все запросы и ответы шифруются AES-256-GCM с ключами сессии (HKDF-SHA256), у каждого сообщения растущий номер, повтор старого сообщения отклоняется. Посредник ничего не расшифровывает.
* **Только нужный сайт.** Программа отдаёт только записи, адрес которых совпадает с сайтом вкладки: тот же домен или его поддомен (`accounts.google.com` получит запись для `google.com`, а `bank.com.evil.example` не получит запись для `bank.com`). Пароль для https-записи не отдаётся на http-страницу.
* **Только по действию пользователя.** Пароль уходит на страницу, только когда пользователь выбрал вход в окне расширения или нажал Ctrl+Shift+L (⌘⇧L на Mac), и только в верхний фрейм вкладки. Вопрос «Сохранить пароль?» нарисован в закрытом shadow DOM и принимает только настоящие клики.
* **Блокировка.** Блокировка программы (вручную или по таймеру) обрывает все сессии. Заполнение и сохранение из браузера считаются активностью и откладывают авто-блокировку. Время авто-блокировки выбирается в Settings (5–60 минут).
* **Разблокировка из браузера.** Пока программа заперта, окно расширения просит мастер-пароль. Пароль шифруется ключом из одноразового ECDH-обмена и ключа разблокировки, который браузер получил при подключении, поэтому отправить его может только подключённый браузер. Неверные попытки считаются в общий лимит (5 попыток, затем пауза 5 минут). Ключ разблокировки хранится в программе открыто, иначе им нельзя было бы воспользоваться при запертом хранилище; сам по себе он ничего не открывает без мастер-пароля.
* Подключённые браузеры видны в Settings → Browser extension, там же их можно отключить или выключить расширение целиком. После смены мастер-пароля браузеры остаются подключены.

## Проверки

* `pytest tests/test_browser_bridge.py`: сопоставление сайтов, сопряжение, сессии, повторы и подмена сообщений, все действия, посредник с настоящим локальным сокетом.
* `pytest tests/test_browser_bridge_js.py` (нужен Node.js, иначе пропускается): `crypto.js` и `background.js` расширения против программы через настоящего посредника.
* Обработчик Safari и сборка под macOS проверяются только на Mac.
